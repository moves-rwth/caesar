A *generator* starts with a counter of one, doubles it on every flip of a fair coin, and returns it after the first heads.
A *countdown* decrements its input to zero.
Each program has finite expected runtime for every fixed input.
Running the countdown on the generator's output has infinite expected runtime <Citation {...references.runtime} locator={undefined} />.

The counter is unbounded, and we count one tick per flip or decrement.
With [`@ert`](../../proof-rules/approximations.md#calculus-annotations) and `post 0`, the specifications bound the expected tick count.

## The Two Programs

### The Generator

Caesar verifies that the generator takes at most two coin flips on average.

## Their Composition

Caesar verifies that every natural number is a lower bound on the expected runtime of the composed program.
The expected runtime is therefore infinite.

<ExampleSources exampleId="runtime-composition" sources={[{
  variantId: 'main', code: source, downloadUrl: download,
  title: 'Arbitrary Lower Bound on Expected Runtime',
  start: '@ert\nproc composition(', highlight: '1,3-4,8,10-12,14,16-17',
}]} />

Stopping on flip $k$ has probability $2^{-k}$ and leaves $2^k$ decrements, so each possible stopping time contributes $2^{-k} \cdot 2^k = 1$ tick to the expected countdown cost.
The generator's [omega invariant](../../proof-rules/omega-invariants.md) adds these contributions, and the countdown's supplies the cost when the generator stops.
The target appears only in the proof, so every bound applies to the same program.

The composition terminates almost surely because the first heads arrives with probability one and every resulting countdown is finite.
