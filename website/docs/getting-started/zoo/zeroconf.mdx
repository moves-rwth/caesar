IPv4 Zeroconf lets devices choose local network addresses without manual configuration or a DHCP server <Citation {...references.rfc} locator={undefined} />.
A device sends *probes* to check whether another device already uses its chosen address.

Lost probes or replies can leave a conflict unnoticed, while additional probes cost traffic and delay <Citation {...references.prism} />.
For one address choice and a fixed probe limit, we verify an upper bound on the probability that the address is free or the collision is detected.
Both outcomes count as `success`.

## The Program

The functions `probCollision()` and `probMessageLost()` give the collision probability $c$ and the probability $q$ that a probe fails to detect it.
This can happen if the probe or its reply is lost.
The function `maxTries()` gives the probe limit $M$.
The helper `exp(q, k)` denotes $q^k$.

<ExecutionDiagram kind="zeroconf">

The procedure `zeroconf` first samples whether the address is occupied.
For an occupied address, it calls `arp(maxTries())` to try to detect the collision.

## Verification {#verification}

Both coprocedures use the [`@wp` annotation](../../proof-rules/approximations.md#calculus-annotations) to verify upper bounds on the probability that `success` is true.

### Upper Bound for the Address Choice {#avoiding-an-undetected-collision}

Caesar verifies the upper bound

$$
\Pr(\mathtt{success})\le (1-c)+c\cdot\left(1-q^M\right).
$$

The term $1-c$ accounts for a free address, which immediately succeeds.
The term $c\cdot(1-q^M)$ accounts for an occupied address, using the bound in `arp`'s specification for $M$ probes.

### Bounding Collision Detection Recursively {#detecting-a-collision}

The helper `arp(triesRemaining)` probes an occupied address, stopping when a collision is detected or no probes remain.

<ExampleSources exampleId="zeroconf" sources={[{variantId: "main", code: source, downloadUrl: download, title: "Detecting a collision with the remaining probes", start: "@wp\ncoproc arp(", end: "\n@wp\ncoproc zeroconf()", highlight: "3-4,6-8,13"}]} />

With $k$ independent probes left, the collision remains undetected if all fail, an event of probability $q^k$.
With no probes remaining, `arp` returns `false`, matching the bound zero.
For $k>0$, a probe detects the collision with probability $1-q$; otherwise, we use the recursive specification with one fewer probe:

$$
(1-q)+q\cdot\left(1-q^{k-1}\right)=1-q^k.
$$

Each recursive call decreases `triesRemaining`, so the procedure terminates after at most that many probes.
Caesar uses the recursive definition of `exp` for $q^k$ and the axiom `exp_bounded` for $q^k\le1$.
